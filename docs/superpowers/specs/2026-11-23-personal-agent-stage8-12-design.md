# 第八到十二课设计

用户授权一次完成后续课程，并要求 Web 清晰呈现执行过程，测试仅保留核心流程。

## 交付

第八课实现 Markdown 与源码目录的持续关注。扫描复用资料白名单和内容指纹，检测变化后创建不可变资料快照、事件与待执行记录。事件记录检测、规则判断、派发与关联运行 ID。支持观察、自动执行、单次批准、暂停、停止和手动扫描，配置检测间隔与每日预算。程序负责检测，模型负责研究。

第九课增加持久 Inbox。运行时在模型请求前应用输入，在完整工具批次后保存输入应用状态。补充消息使用稳定 ID 去重。停止在安全边界生效，已发出的工具操作须完成并回填。ask_user 工具将任务置为等待回答，释放执行槽位，用户回答后恢复。原消息和模型实际输入实时可见。

第十课实现持久 Outbox 和站内通知。成果生成与投递状态独立。通知使用稳定 ID 写入本机通知文件，再保存送达状态，崩溃重试核对同一文件。暂停投递、失败重试、已读回执均在页面可见。每项通知和任务相关联。

第十一课管理页面展示关注项、事件、任务、通知及当前阶段。允许两项任务同时执行，单项任务等待用户不阻塞其他任务。每个任务保留模型输入、完整消息、工具参数和结果、计划、纠正输入与检查点，支持停止、回答及恢复。

第十二课提供显式长期目标与偏好，保存内容、关键词、目录范围及观察/自动规则。匹配目标作为运行上下文，记录本次引用来源。匹配的研究委托可产生持续关注建议，观察模式先展示建议，自动模式只在已配置目录范围内启用关注。支持停用目标和拒绝建议。

## 一致性

Web 运行目录延续进程独占锁。主动服务状态以单份版本化 JSON 原子提交，执行意图先落盘再派发，派发使用确定性运行 ID，重启核对运行记录，避免再次创建同一研究。资料快照固定输入版本。若历史已淘汰且同 ID 检查点存在，停止重复创建并提示核对。停用关注阻止新任务，停止关注同时请求停止关联未完成研究并撤回未投递通知。

Inbox 应用写入原始消息和检查点后确认，重复恢复可识别消息 ID。检查点允许工具批次之间的用户消息。上下文压缩保留后续要求。执行结果不确定的检查点延续人工核对机制。

## 核心验证

覆盖资料变化触发与去重、观察后批准、执行中补充/问答/停止、投递暂停后重试，以及长期目标建议与服务重启持久化。使用回放与可控模型验证确定性路径，浏览器检验管理页面全过程。真实 DeepSeek 沿用同一执行入口与 .env。
