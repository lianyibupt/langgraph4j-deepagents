# Agent 长任务调试手册

## 一、记录目标

启动调试前写下用户目标、验收条件与资料范围。运行时每轮构造模型输入时，检查最初的目标是否仍然可见。多轮工具调用期间，临时错误和搜索结果会累积，容易淹没任务约束。对照原始目标可以判断模型的下一步是否合理。

先建立三个短步骤。第一步读取资料，第二步检查工具结果和证据，第三步汇报结果。任务变化时可以重新安排步骤，已经完成的工作应有可检查的结果。计划状态只记录执行进展。

## 二、检查调用与回填

模型收到消息和工具定义后，可以输出最终答案，也可以提出工具调用。工具在程序侧执行。检查助手消息里的调用编号和工具结果里的编号是否一致。一次响应可以包含多个调用，给模型构造下一轮输入时应保持这批调用与对应结果的顺序。

在本地断点观察工具参数、运行时状态与输出内容。用户提问、模型发起调用和工具执行三者各有自己的数据边界。文件读取失败时记录可观察的错误，并让模型根据错误选择下一步。

## 三、处理长结果

当工具返回大量文字时，把原文保存为当前任务的产物。给模型返回产物编号与长度，模型可以按需读回一段。原文和引用说明都应能独立查看。执行摘要里记录状态和索引，引用事实时查看实际文本。

读回原文要遵循工具返回的下一段偏移量。一次只读当前判断需要的片段，避免让结果再次淹没目标。检查终端日志中的保存路径和字数，确认归档文件包含工具实际返回的文本。

## 四、检查上下文预算

在每轮调用前比较完整历史与模型实际收到的消息。检查最初的任务目标、当前计划、最新一批工具调用及其结果是否保留。较早的批次可以压缩成状态摘要，完整历史仍可用来排查。

字符预算衡量文本和工具参数的大小，用于这个实验的可复现调试。模型供应商按自己的 tokenizer 和请求协议计算 token，二者口径不同。最新批次和计划超过预算时应给出明确的停止原因。

## 五、复查执行状态

观察每轮的工具名、执行状态、结果长度和产物编号。到达轮次上限时检查停止原因，必要时保存已有证据。工具失败后，计划里依赖该结果的步骤应保留为未完成，或者明确说明采用了其他方法。

结束前核对报告中的事实、推断与出处。确认完成状态反映真实执行结果，并在仍有不确定性时列出待核对的问题。这个实验可以反复运行，比较不同预算下保留的工具批次。

## 六、练习

把预算调小后观察第一次发生压缩的位置。再给一个较长的用户目标，观察预算检查如何在模型请求前停止。最后读取一个缺失文件，检查错误是否仍出现在可见上下文，以及计划有没有被错误地标成完成。

完整资料结束。
